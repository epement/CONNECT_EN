[Instructions for the CN Help Compiler]

This program is designed to convert a text file into a help file that is
format-compatible with the file `CONNECT.HLP (Turbo Vision Help File)`.
The source file format for the `cnhc` utility is very simple.

[1. Topic identifiers.]

A topic identifier must begin with the word `.topic` at the first
position of the line.  It may be followed by one or more identifiers used
to reference this specific context. An identifier consists of a sequence
of characters from the sets A..Z, a..z, _, and the digits 0..9, and must
begin with a letter.  Identifiers are separated by commas.  For example:
ÚÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄ¿
³.topic movs, movsb, movsw, movsd³
ÀÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÙ
defines a single context for multiple references simultaneously.


[2. References.]

A reference consists either of the link text [i.e., the identifier]
enclosed in curly braces, or else arbitrary text followed by a colon and
the name of the topic identifier.  In the first case, the reference
`{MOVS}` points to the topic declared by the identifier `movs`. The case
of the identifier is ignored [i.e., it can be entered in uppercase or
lowercase. The word "MOVS" will be highlighted as a hyperlink in the help
file].

In the second case, a reference such as `{String transfers:movs}` may be
used, which also points to the `movs` identifier. [In the help menu, the
user will only see the words before the colon; choosing that option will
take them to the destination linked after the colon.]

[Note that the beginning and ending curly braces {...} cannot wrap across
two or more lines. A reference must fit on a single line.]


[3. Special characters in references.]

[Since references are defined by braces and colons, those characters must
be treated specially inside references.]

If the help text needs to contain the characters `{` and `}`, they must
be replaced in the `cnhc` source file with the characters corresponding
to [ASCII decimal] codes 243 and 242 (0xF3, 0xF2), respectively.

If the link text needs to contain the character `:`, it must be replaced
with the character corresponding to code 247 (0xF7).


[4. Beginning a line with a dot.]

[The dot at the start of a line normally signifies a compiler directive,
such as ".topic" or ".include another-file", so you should avoid
beginning a paragraph with a dot.  But] if a line of help text needs to
begin with a `.`, replace it with the character corresponding to ASCII
decimal code 249 (0xF9). [In both codepage 437 and 866, this character
looks like a slightly elevated dot "ù", and it should be converted to a
period when displayed in the Connect help menu.]


[5. Controlling word-wrap.]

When the help file is displayed, lines starting at the first character
position [i.e., column 1] are automatically wrapped to fit within the
window.

Lines starting with a space are displayed without wrapping.


[6. Comment lines.]

Lines with a `;` in the first column are treated as comments and are
ignored by the help file compiler.

To include a line in the help file that actually begins with a `;`, it
must be written as `;;` in the source text.


[7. Include files.]

It is possible to construct help text from multiple files. This is
accomplished using the keyword `.Include filename`, which must appear at
the very beginning of a line. Included files may be nested up to 50
levels deep. The `filename` can be specified either as a full path or
simply as a filename. In the latter case, the included file is first
sought in the current directory, and then in the directory where the main
help file is located.


[8. Colorized or invisible links.]

Special pseudo-topics `Color_1`, `Color_2`, through `Color_5` are reserved;
a link to one of these causes the link text itself to be displayed in the
corresponding color, as configured in the "Colors | Help window" dialog.

The pseudo-topic `Color_X` renders the link text invisible. [This means
that the label works as a destination to jump to, but the label itself
will be invisible; the text below the label will display normally. See
section 10, below.]

The pseudo-topic `AbsColor_NNN` sets the text attributes for the link,
where `NNN` is a decimal or hexadecimal value.


[9. Links to other help files.]

The pseudo-topic `OtherHelpFile` allows you to create a link to the default
(zero) context of a specified help file. For example:

the file containing the link. A different and more flexible method for
achieving this is described below [in section 13, "Advanced features of

[10. Linking to sections of a topic.]

If a link label [immediately after the colon] begins with the character
0x19 (ASCII #25), then upon activating that link, the system searches
through the links and pseudo-links within the target topic to find a
match for the link text itself. For example, suppose the following links
are defined: [Note the char 0x19 before the first 2 labels; it should

When following the `Text1` link, the help system will display the topic

display the topic "Text" from the very beginning.  When navigating to the
pseudo-link `Color_X`, the help system will place the cursor on the line
immediately following that pseudo-link; when navigating to visible links
or pseudo-links, the cursor is positioned directly on that link.


[11. Topic limits.]

The total number of topics must not exceed 16,384.


[12. Launching external programs.]

It is possible to launch external programs directly from within the help
system.  To do this, you must create a special context (topic) where the
first line contains the keyword `$Execute`, the second line specifies the
program's path, and the third line contains the command line arguments for
the program being launched. All standard command-line macros are supported.
Thus, the following help snippet executes the command `arj -?` and opens a
viewer to display the resulting help output.

³                                                       ³
³.topic arj                                             ³
³ $Execute                                              ³
³ arj $Msg $NoMsgWin $NoReread $NoReDraw; $View($Report)³
³ -?                                                    ³

[13. Advanced features of the $Help macro.]

The command-line macro `$Help()` can accept a parameter specified directly
on the command line. When such a macro is invoked, the help system searches
for this parameter within the first context (topic) and navigates to it
if found. Thus, it is now possible to create links from one help file to a
specific context within another.
ÚÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄ¿
³ {The Built-in Assembler:basm} ³
³                               ³
³.topic basm                    ³
³ $Execute                      ³
³ $Help($cn\help\turbo.hlp)     ³
³ $Word                         ³
ÀÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÄÙ

When a help file created in this manner is integrated into `CONNECT`,
pressing `F1` while within it opens the topic defined as the first entry in
the help file; pressing `Ctrl-F1` opens the second topic, and within that
topic, an `Incremental Search` is performed, searching through the links
for the word currently under the editor's cursor. Consequently, the first
topic (`topic`) in the help file should contain general links to the help
system's topics, while the second should contain a list of links
specifically for context-sensitive searching. The topic number can be
explicitly specified by adding the line `.topic First=0`.


[14. Compiling large help files.]

The file `CNHCX.EXE` along with the auxiliary files `RTM.EXE` [Run-Time
Manager] and `DPMI16BI.OVL` [DOS Protected Mode Interface] enables the
compilation of large help files on `286+` machines equipped with extended
memory. [Try CNHCX.EXE if you run out of memory with CNHC.EXE.]


[15. Handling error messages.]

All text below this line is by Eric Pement.

15.1. Compiler error messages.

A message like "Error: CN_EN.TXT(211): Unterminated topic reference"
means that for the file CN_EN.TXT, a brace-delimited topic reference was
not closed. That is, one of the braces was missing, or else the brace was
opened "{" on one line and closed "}" on a different line. The number in
parentheses shows the line number where the error occurred.

Warning: FILE(1388): Unresolved forward reference "PlaceMarkerDlg window"
means that on line #1388, a brace-delimited topic reference had 2 words
following the colon-separator, "PlaceMarkerDlg window", when it expected
only one word. This was a fault of the translation mechanism. Remove the
space and the word "window", save, and recompile.

15.2. DOS line endings required.

Input files must have standard MS-DOS line endings, in which each line
ends in 2 consecutive bytes: carriage return+linefeed or (0x0D+0x0A).
On Unix or Linux systems, text and source code lines end in a single
byte: LF (linefeed), or 0x0A.

If the input text file has Unix line endings, the help compilers CNHC.EXE
or CNHCX.EXE will emit this message:

  Error: filename.txt(6): Unterminated topic reference.

The compiler will close and send exit code 1 to the operating system. To
fix the problem, convert the file to DOS-style line endings with a
program like "unix2dos" or from within the text editor itself.
